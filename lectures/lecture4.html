LECTURE 04

HTML Structure and Forms

Learn how to organize webpage content with semantic elements and collect user information using HTML forms.

Lecture Video

Watch & Learn

About This Lecture

HTML provides different elements to organize webpage content. Some elements are used for layout, while others describe the meaning of content. HTML forms allow users to enter information such as names, email addresses, messages and preferences.

This lecture covers block and inline elements, semantic HTML, form controls and built-in browser validation.

What You'll Learn

HTML Structure

Understand block, inline and semantic elements.

HTML Forms

Collect user input using different controls.

Validation

Check user input with HTML5 attributes.

1. Block-Level and Inline Elements

Block-level elements normally begin on a new line and take up the available width. Examples include div, p, h1 and section.

Inline elements usually remain within the same line and take up only the space they need. Examples include span, a, strong and em. 

<div>
     This is a block element.
</div>

<p>
     Learn <strong>HTML</strong> with WebLearn.
</p>

<span>This is inline text.</span>
<a href="about.html">About Us</a>

div and span

The div element groups content into a block-level container. The span element groups a small piece of inline content. Both are commonly used with CSS. 

<div class="card">
     <h2>HTML Course</h2>
     <p>Learn the basics of HTML.</p>
</div>

<p>Learn <span>HTML</span> today.</p>

2. Semantic HTML Elements

Semantic elements describe the purpose of their content. They make HTML easier to understand for developers, browsers and assistive technologies.

  • header: Introductory content or a page heading.
  • nav: Navigation links.
  • main: The main content of the page.
  • section: A group of related content.
  • article: Independent content, such as a post.
  • aside: Related or supplementary content.
  • footer: Footer information.

Example of Semantic Layout

<header>
     <h1>My Website</h1>
</header>

<nav>
     <a href="index.html">Home</a>
     <a href="about.html">About</a>
</nav>

<main>
     <section>
          <h2>Web Development</h2>
          <p>Learn how websites are built.</p>
     </section>

     <aside>Related resources</aside>
</main>

<footer>
     <p>WebLearn</p>
</footer>

Accessibility and SEO Benefits

Semantic HTML helps screen readers identify page sections and makes content easier to navigate. Search engines can also better understand the structure and meaning of webpage content. Semantic elements alone, however, do not guarantee higher search rankings.

3. HTML Forms

Forms collect information from users. The form element groups input controls together. Its action attribute specifies where the form data is sent, and its method attribute specifies how the data is submitted.

  • action: Specifies the destination for submitted data.
  • method="get": Usually sends data as URL parameters.
  • method="post": Sends data in the request body.

Input Types

The input element supports different types for collecting different kinds of information. 

<form action="/submit" method="post">

     <label for="name">Full Name:</label>
     <input type="text" id="name" name="name">

     <label for="email">Email:</label>
     <input type="email" id="email" name="email">

     <label for="password">Password:</label>
     <input type="password" id="password" name="password">

     <label for="age">Age:</label>
     <input type="number" id="age" name="age">

     <button type="submit">Submit</button>

</form>

Other useful input types include checkbox, radio, date, file and tel. The name attribute identifies the field when its value is submitted.

Select Dropdown

The select element creates a dropdown list. Each option represents a choice. 

<label for="course">Choose a course:</label>

<select id="course" name="course">
     <option value="html">HTML</option>
     <option value="css">CSS</option>
     <option value="web">Web Development</option>
</select>

Textarea

The textarea element allows users to enter longer text, such as comments, feedback or messages. 

<label for="message">Your Message:</label>

<textarea id="message" name="message"
     rows="4" cols="30"></textarea>

Buttons

Buttons perform actions in a form. A submit button submits the form, while a reset button restores form controls to their initial values. 

<button type="submit">Submit Form</button>
<button type="reset">Clear Form</button>

4. HTML5 Form Validation

HTML5 includes attributes that help browsers check user input before submitting a form. These checks improve usability, but server-side validation is still important.

Required Attribute

The required attribute prevents submission when a required field is empty. 

<input type="text" name="username" required>

Pattern Attribute

The pattern attribute checks whether text matches a specified regular expression. Here, the username must contain 4 to 12 letters or digits. 

<input type="text" name="username"
     pattern="[A-Za-z0-9]{4,12}"
     required>

Min and Max

The min and max attributes define the allowed range for number and date controls. 

<label for="age">Age:</label>

<input type="number" id="age" name="age"
     min="18" max="60" required>

Complete Form Example

The following example combines labels, different input types and validation attributes. 

<form action="/register" method="post">

     <label for="username">Username:</label>
     <input type="text" id="username"
          name="username" required
          pattern="[A-Za-z0-9]{4,12}">

     <label for="email">Email:</label>
     <input type="email" id="email"
          name="email" required>

     <label for="age">Age:</label>
     <input type="number" id="age"
          name="age" min="18" max="60">

     <button type="submit">Register</button>

</form>

Note that the example demonstrates HTML structure only. The form needs a suitable server endpoint to process submitted information.

Key Point

Use semantic elements to organize content and accessible labels to describe form controls. HTML validation improves the user experience, but it does not replace server-side validation.
